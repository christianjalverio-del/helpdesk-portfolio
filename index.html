Featured Project — Home Network & Server Build

The same troubleshooting habits I use every day with customers, I applied here: a fully self-built home network and server infrastructure, built incrementally over several months, where I ran into and worked through a long list of real hardware, software, and networking problems — the kind of systematic, root-cause diagnosis this role calls for. Along the way it grew into a full environment covering firewall administration, VPN-based remote access, network storage, and a virtualization host.

Selected Troubleshooting

A few concrete examples of root-cause diagnosis performed during this project:

  • Traced a VPN client showing zero received traffic to a WAN interface setting silently dropping private-sourced packets, rather than assuming a misconfigured tunnel.
  • Diagnosed a browser certificate rejection (NET::ERR_CERT_VALIDITY_TOO_LONG) back to a self-signed certificate exceeding the modern 398-day maximum validity policy, not a trust-chain problem.
  • Isolated a file-share permission failure to a parent directory's restrictive Linux permissions several levels above the actual shared folder, resolving it with a scoped bind mount.
  • Identified a severe server performance issue as CPU/I-O contention between a background data pre-generation task and live usage, resolved with an automated pause/resume mechanism.

Environment

  • Physical topology: ISP fiber gateway to pfSense firewall/router to segmented internal LAN, running behind a double-NAT boundary.
  • Core infrastructure: pfSense CE (firewall/router/VPN/IDS), TrueNAS SCALE (network storage), Proxmox VE (virtualization host) — TrueNAS and Proxmox each run on their own dedicated mini PC.
  • Remote access: self-hosted WireGuard VPN, no reliance on third-party mesh VPN services. Access is scoped per peer at the firewall — full LAN access for trusted devices, single-host access for everyone else, as shown in the topology diagram below.
  • Virtualized/containerized services: Docker (via LXC on Proxmox), managed through Portainer.

Network Topology

Physical Build

The infrastructure runs on a compact wall-mounted 10-inch rack, built and wired from individual components — including the NETGEAR switch, HDD caddy, JetKVM for out-of-band access, and custom 3D-printed mounting brackets designed to fit the rack's non-standard dimensions. TrueNAS and Proxmox each run on their own dedicated mini PC, with the NAS drive's power and data cabling routed through a cutout added to the TrueNAS unit's case.

Network Security & Firewall (pfSense)

Configured and administer a pfSense firewall as the network's perimeter defense, managed through both the web GUI and direct SSH access. On the WAN side, firewall rules follow a least-privilege, default-deny model — inbound traffic is blocked by default except for two explicitly scoped allow rules (the WireGuard VPN and the Minecraft server), each locked to a single destination host and port. The LAN side is trusted, physically-controlled hardware and is intentionally left open internally, since access control for less-trusted traffic is enforced separately at the WireGuard interface rather than at the LAN rule set. Set up DHCP (Kea), DNS resolution, NTP, and system logging, and configured WAN-facing settings deliberately, including reasoning through bogon vs. private-network filtering trade-offs when they conflicted with legitimate internal testing traffic.

VPN Infrastructure (WireGuard)

Replaced a third-party mesh VPN with a fully self-hosted WireGuard deployment on pfSense, including port forwarding through a double-NAT ISP gateway. Designed a tiered access model using firewall aliases: my own devices receive full internal network access, while every other peer — family and friends I've onboarded so far — is restricted by default to a single internal host, enforced entirely at the firewall layer rather than by trusting client configuration. Generated and distributed per-peer keys and preshared keys for each device, and diagnosed a real-world NAT hairpin/reflection issue that was silently dropping same-network test traffic, tracing it back to a WAN interface bogon-filtering setting.

Intrusion Detection & Prevention (Snort)

Deployed Snort as an active IDS/IPS on the WAN interface, in inline blocking mode rather than passive logging-only mode. Curated rule categories (Snort VRT/Subscriber, Emerging Threats Open, FEODO Tracker, GPLv2 Community, OpenAppID) balanced against the hardware's processing budget, and corrected a self-lockout risk in the block-target configuration before it could firewall off the router's own WAN address. The alert log shows Snort actively catching real inbound traffic, including a hit from Spamhaus's DROP list — a feed of networks known for hosting spam and malicious activity — confirming the rule set is working against live traffic, not just configured and idle. Built a lightweight shell script, scheduled via cron, that tails Snort's alert log and pushes new detections to a Telegram bot in real time.

Virtualization & Self-Hosted Services (Proxmox)

Built and manage a Proxmox VE host running a containerized services environment (Docker inside an LXC container, managed with Portainer and verified directly via the container CLI). Deployed and secured multiple self-hosted applications: Vaultwarden (password manager) behind a Caddy reverse proxy terminating TLS with an internally issued CA certificate — installed and trusted on client devices, and confirmed secure in the browser — and Uptime Kuma for service and endpoint monitoring with Telegram alerting. Scheduled automated Proxmox backups of the LXC container to TrueNAS over NFS, running on both a daily and weekly schedule with retention limits, and confirmed successful snapshot storage on the NAS side. Diagnosed and resolved a chain of real infrastructure issues along the way, including Docker's default directory permissions blocking a file share, NAT/port-forward misconfigurations, and container resource sizing.

Storage, Backup & Access Control (TrueNAS)

Administer a TrueNAS SCALE server providing network storage for personal files, media, and application data. Organized storage into multiple datasets with scoped permissions, configured SMB and NFS shares with host/network access restrictions, and set up UPS monitoring (NUT) with a properly configured monitor user after diagnosing an initial misconfiguration. Receives and stores the scheduled backups pushed from the Proxmox host over NFS, and runs a small set of self-hosted apps directly on the NAS.
